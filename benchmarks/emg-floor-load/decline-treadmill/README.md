# Predicting the load on a downhill treadmill

[Run the browser model](https://eliminatenoise.github.io/NeuroTranslation/walking-force/decline/) · [Technical edition](TECHNICAL.md) · [Download the offline comparison and checkpoints](https://raw.githubusercontent.com/eliminatenoise/NeuroTranslation/main/benchmarks/emg-floor-load/decline-treadmill/Decline-Treadmill.zip)

A small model learned from six people walking down a 5° treadmill. We then used it to predict the load from four other people walking down a steeper 10° treadmill. With the answers scaled using each person's measured body mass and the slope, its average error was **9.579 newton-seconds**. A rule based on body weight on that slope missed by **16.325**. The small model reduced error by 41% overall and helped for all four people. In the comparison using muscle readings alone, a simpler fit did best and improved on its fixed reference for two of four people. [All 22 comparisons](TRANSFER-RESULTS.json)

## What the treadmill measured

Each of the two belts has a plate that measures force. We added up the force at right angles to the plate over a tenth of a second. That gives a quantity called **impulse**, measured in newton-seconds or N·s. A force of 100 newtons held for one tenth of a second gives 10 N·s. Pushing into the plate contributes a positive number. Plate 1 and plate 2 are named in the order they appear in the recording.

The main score is for the total. We add the two plate forecasts, add the two measurements, and calculate how far apart the totals are. Opposite mistakes on the two plates can cancel in that score. The viewer also shows the errors on each plate. We first average each person's errors, then give everyone the same weight, so the person who supplied the most readings cannot dominate the result.

Both plates had readings in all 708 forecast windows. To use a person in the separate-plate comparison, we required both plates to register at least one impulse greater than 10 N·s. We also required, for each plate, at least one window when it registered more than 1 N·s and the other registered 1 N·s or less. One person did not have a window when plate 1 dropped to that level. That person's 174 forecasts still count toward the total. The separate-plate results use 534 forecasts from the other three people. The screen concerns measured belt load, and the data here do not establish which foot was on each plate.

## What the forecasts received

Electrodes on the skin picked up the small voltages associated with muscle activity. We used six channels. On each leg they came from the biceps femoris at the back of the thigh, tibialis anterior at the front of the shin and rectus femoris at the front of the thigh. Each forecast uses 400 earlier readings from one fifth of a second in the archive. There is a gap of 10 milliseconds before the forecast begins, with the final included sample at tick 21 before issue. The stored clock has 2,000 sample positions per second. The instruments originally sampled at different rates, and their physical delays still need to be measured. [How the original recordings were collected](https://doi.org/10.1038/s41597-023-02840-6)

We divide the readings into ten groups of 20 milliseconds. In each group we measure how much the voltage varies around its average. We use the first three groups to establish a reference. Starting with the fourth group, the input says how large that group's variation was compared with all the earlier groups. We take the square root of the ratio, add one and take a logarithm so unusually large values have less influence. The model uses seven such numbers per muscle and knows which groups have an observation.

The models always read muscle features. In one comparison we leave the body mass and slope out. The fixed rule then predicts the typical combined load seen while fitting. In the other, the fixed rule estimates how much a stationary person's weight pushes into the sloping surface over the same time. We divide the original impulse by that estimate when fitting those models and multiply their answers by it to convert back to newton-seconds. These are two independently fitted model sets with different output scales.

## How the models compared

We fitted the models on 1,060 windows from the six people on the 5° treadmill. We then saved all 22 forecasts for 708 windows from four different people walking at 1.2 metres per second on the 10° treadmill in the same lab. We fixed the exact samples to check before reading their force measurements. A separate check read 283,200 distinct force values and reproduced the scores. Some of the four people supplied other recordings for previous project studies.

The linear model learns a multiplier for each input, then adds the results. The compact model also learns how to weigh readings in relation to each other. It runs the same calculation block one, three, five, seven or nine times. The block represents each group with 32 numbers, uses four groups of comparisons and has an internal layer with 64 values. Each variant learned from 48 trips through the training set, 128 examples at a time. It weighted people equally and learned from errors on both the individual plates and their combined load. The fitting settings were a learning rate of 0.001 and an adjustment of 0.0001 that limits large weights. We averaged two fits that started from different values. Using an already-loaded model, five, seven and nine passes took about 22, 29 and 35 milliseconds respectively for 708 prepared windows. That timing covers the model calculation on this machine.

The larger Research Edition ran three passes and produced a summary containing 2,304 numbers for each forecast. The calculation used 32-bit arithmetic on the publisher's stored packed weights. We kept the summary calculation fixed and trained new output equations at 64-bit precision. One equation sees just the same 42 muscle features as the compact model. Another sees just the Research Edition summary. A third sees both. We also tested a weighted average of the first two answers. The weights learned from the earlier group gave the Research Edition answer zero weight in both conditions. In each condition the average equals that condition's relative-muscle forecast, including its mass-and-slope scaling when supplied.

| Average error for both plates combined, in N·s | Muscle alone | Muscle, body mass and slope |
| --- | ---: | ---: |
| Fixed reference | 23.063 | 16.325 |
| Linear fit | 21.875 | 11.009 |
| Compact, five passes | 23.775 | 9.715 |
| Compact, seven passes | 24.387 | 9.633 |
| Compact, nine passes | 25.521 | 9.579 |
| Full Research Edition output fit | 22.935 | 14.769 |

| Weighted average of the two forecasts | 21.877 | 11.322 |

In the comparison that supplied body mass and slope, nine compact passes had the lowest total error. Seven passes were within 0.053 N·s and led for two of the four people in the direct comparison. Without body mass and slope, the linear fit averaged 21.875 N·s, with lower error than the fixed rule for two of the four people. Every compact variant had a higher average than the fixed rule in that condition. Four people give us a limited view of how the results would carry over. ## Earlier 5° recordings

In a separate experiment we used body mass and slope plus different ways of measuring movement. We used the same 1,060 earlier windows, held each of the six people out in turn and fitted on the other five. The static reference missed by 16.204 N·s. The muscle readings missed by 10.362. Eight wearables, which measure how quickly their motion changes, gave 6.558 using the size of their acceleration. Combining muscle and wearable readings gave 6.218, reducing error from muscle alone for all six people.

A fit using the earlier path of two camera-tracked landmarks on the front of the pelvis gave 3.727 N·s. We used their midpoint for every person and checked the wearable units against the authors' files. Treating the motion of those points as an estimate of the mechanical acceleration gave a larger error, 25.816 N·s. The midpoint is an estimate of how the front of the pelvis moves. The steps the stored positions went through and the time at which they would have been available live are uncertain. Neither camera nor wearable inputs were used in the 10° comparison. [All movement measurements and results](MOVEMENT-RESULTS.json)

The folder also keeps the earlier 5° held comparison. That test used a different summary of 16 muscle signals. Its main result used 539 forecasts from three people. Three compact passes over 200 milliseconds gave a mean plate error of 21.97 N·s, against 26.79 for the typical load from fitting. Five passes over one second gave a combined error of 19.30 rather than 30.32 N·s. The linear model with one second of readings gave the lowest average squared error for the chance of load, 0.1326 versus 0.2192 for the fixed chance. Some rankings changed when all 712 forecasts from four people were included. ## Run the forecast in a browser

Open the browser model above, or extract the ZIP and open **Run Forecasts.html**. The extracted folder also has **Open Forecast on Linux.sh**, **Open Forecast on macOS.command** and **Open Forecast on Windows.cmd**. The forecast works offline with the files in the folder. Starting the browser model only needs a browser.

1. Start with the invented voltage example. Choose a muscle to see its 400 readings. Change **Voltage in the shaded interval** to strengthen or weaken that muscle signal in the last 140 milliseconds of the history. The grey trace shows the original voltage when you make a change.
2. Choose a compact model with 1, 3, 5, 7 or 9 passes. Try the model with and without mass and slope scaling. The invented example starts with 72 kg and −10°. The three fitted rows show the next tenth of a second of load for each plate and for both added together. The fixed rule provides a combined load alone.
3. Use **Open a voltage CSV** to try 400 earlier rows of readings in volts at 2,000 samples per second. Leave a 10 ms gap between the history and the start of the forecast. If your recording is in microvolts, divide each reading by one million. Use the six channel names below, one sample per line and ordinary numbers with or without quotes. The file stays in your browser. Opening it clears the invented body mass and slope, and the page starts with five passes and muscle readings alone. Enter measured mass and slope together to use scaling for that recording.

The browser uses the same saved model weights as the Python release. Its arithmetic uses the browser’s number operations and a published formula for one step of the compact calculation. We ran the page’s model code in Node.js, which runs JavaScript outside the browser, and compared all five pass counts and the simpler forecasts on the same 708 earlier inputs. The largest difference across 18 combinations of method and scaling, checking the plate numbers and their total, was below **0.00008 N·s**. This compares the programs. The recorded 10° accuracy results above still use the original saved forecasts. The packaged Python runner also accepts a separately generated Research Edition state for the larger model’s output fits. [Handbook formula 7.1.26](https://digital.library.unt.edu/ark:/67531/metadc40302/m1/315/)

We opened the offline page and exercised the browser controls and file reader on Linux. The macOS and Windows launchers have source checks.

## Run the Python forecasts and recorded comparison

1. Download and extract the ZIP, then open **Compare Results.html** in your browser. It needs no connection. Use **Recording group** to move between the 10° test and the earlier 5° comparisons. In the 10° test, use **10° comparison** to compare the versions with and without body-mass and slope scaling. The earlier held comparisons have a menu for their original error measures.
2. To run a forecast, install Python, NumPy and the CPU build of PyTorch for the same Python interpreter. Open a terminal in the extracted folder. On Linux run `sh "./Run Transfer Linux.sh"`. On macOS run `sh "./Run Transfer macOS.command"`. In Windows Command Prompt run `".\Run Transfer Windows.cmd"`. [PyTorch installation](https://pytorch.org/get-started/locally/)
3. The first run reads **Example Muscles.csv**, a file of invented readings. It prints text in JSON format with the plate measurements it predicts and their sum. It uses five passes by default. To try the body mass and slope option, add `--mass-kg 72 --slope-deg -10` to the end of the command. Those are example values. If you use your own recordings, enter the measured body mass and the slope together. Downhill angles use a minus sign. The model defaults to nine passes when given those inputs. Use `--passes` followed by 1, 3, 5, 7 or 9 to try a particular depth.
4. To use your own voltages, pass the name of a CSV file with the header `LBF,LTA,LRF,RBF,RTA,RRF` over exactly 400 rows. Write the values in volts with the same timing as the study and make sure the first three groups contain variation in each muscle. If your readings have already been summarized, use a NumPy file with `relative` arranged as windows by seven groups by six channels and `muscles` listing the same six names. The original **Launch** scripts in the folder still run the earlier model with its earlier example and input format.
5. The small model, linear fit, relative muscle output fit and weighted average run directly. To run the other two output fits, supply an exact Research Edition summary with `--research-state`. The NumPy file needs `representation` with 2,304 numbers for each matching window and scalar entries named `base_checkpoint_sha256`, `relative_projection_sha256` and `passes`. Copy the identity values from the model manifest for the matching calculation. The full base model, its input projection and the export that makes those summaries are separate. [Model manifest](TRANSFER-MODEL.json)

We ran both forecast launchers from the extracted folder on Linux and checked the macOS and Windows launcher source. These comparisons concern recorded treadmill force from one lab. Other movements, laboratories, real-time inputs and using a forecast to control a device each need their own tests.
