# Finger-base angle forecast

Open `index.html` from the extracted folder. Each platform launcher opens that file. Choose the finger and method, adjust the invented history, or import a compatible JSON file.

The model forecasts signed angular change at the base of four fingers eight frames after issue, nominally 320 ms at 25 Hz. `history` contains ten rows with four angles in degrees and optionally sixteen ultrasound tiles. The order is index, middle, ring, pinky followed by a row-major 4×4 tile grid. Restore the stored amplitude scale, compute the mean amplitude of each tile, and apply `log1p`. The browser subtracts the first tile value in each input window for the relative configuration. Calculations and file reads are local. The camera stays off.

The controls retain the last angle or extrapolate a least-squares trend from the last five inputs. Linear fits use a ridge penalty of 0.01. Recurrent fits use 24 internal values, three successive updates, 160 training steps and 64 rows per step. Training uses two fixed seeds and averages their predictions. The export preserves the fitted FP32 tensors and FP64 ridge coefficients. The browser uses FP64 for the main arithmetic and rounds normalized inputs and recurrent states to FP32 at the corresponding steps.

Four leave-one-person-out fitting runs used the same isolated medium-speed index movement, with 5,532 paired windows per finger and equal-person mean absolute error. Index ridge using angles alone scored 20.78°. Joint ridge dropped from 44.38° to 23.45° with relative echo. Joint recurrence dropped from 34.99° to 26.63°. Angle-only recurrence gave 24.09°. Pinky joint recurrence rose from 3.12° to 3.32°. Relative echo reuses the same development outcomes. The runnable models were fitted on all four fitting people. Two other people are reserved, and live delivery time remains unmeasured.
