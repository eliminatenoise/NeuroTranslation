Twenty milliseconds of a grasp

Can one model learn both forecasts?

As a macaque grasps and pulls a sliding object, sensors track its travel and respond to contact and load. Electrodes record brief electrical pulses called spikes. We gave a model the last tenth of a second from both sets of instruments. Then we asked it to forecast the next 20 milliseconds.

Training one task at a time gave lower error

With two forecasts trained together, the object sensor error rose by 0.56 counts in the first fit and 6.19 in the second. The model trained on spike counts alone also scored better in both fits. Lower numbers are better in both tables.

The spike-count penalty is lower when the model gives the recorded counts a higher probability. The score averages all 93 sorted units. We also swapped in the spike history from an earlier trial at the same point in the task and with the same cues. The joint model did worse on both forecasts with the swap. It was sensitive to which trial supplied the spikes.

The same starting weights

All fits kept the original seven-task NeuroTranslate Transformer fixed. They trained new layers from the same initial values. One version learned to forecast sensor changes. One learned spike counts. The third trained both readouts together. Every version received the same past physical readings, spikes and task cues.

We scored 1,465 windows from 20 original trials. Those trials came from the earlier study’s fit set. The two fits used the same evaluation trials, and each trial had equal weight. The authors sorted spikes after recording. Live decoding and performance on another animal remain untested.
