Recent movement gave the lowest tail-variation forecast error

A camera filmed the bends of a zebrafish's tail. We used its earlier readings to forecast how much the angle would vary over the next tenth of a second. Keeping the same amount of variation as the recent past gave the smallest average miss. The fitted camera rule came next. In this comparison, adding the recorded visual command to that rule raised the average error by 0.000572 radians across the same 2,268 cases.

Forecast Average size of the miss (radians)
Keep the amount of variation from the last tenth of a second 0.011266
Use measured camera history to adjust that amount 0.013926
Use the camera history and the logged visual command 0.014498
Use the camera history and the same command readings six seconds further back 0.014164

The angle and the command

The source is the recording labelled fig4_01/230413_f1 in Ryosuke Tanaka and Ruben Portugues's study. A program decided when to move a visual pattern forward or backward. The log records the direction in a field called LDPS_drift_direction, as −1 or +1. We found 1,735 changes at distinct, increasing times. These times come from the computer's log. When the pattern physically changed on the screen, or when the fish saw the change, remains unverified.

The camera's angle measurement is called tail_sum. The sign records which way the tail bends. Its size records how far it bends, measured in radians. We used the spread of the signed angles. This is called the population standard deviation. To calculate it, find the average angle, square the distance of every angle from that average, average those squares, and take the square root. A tail can stay bent in one direction and still have a small spread. The stored target uses 19 to 21 camera readings from the tenth of a second that starts at each forecast time and ends just before the next tenth of a second.

How we chose the examples

We considered forecast times 320 milliseconds apart, counted from zero on the software clock. Some neighbouring entries shared a timestamp. There were 10 such pairs in the camera log and 2,175 in the display log. The two command readings in every display pair agreed. We omitted both entries in pairs in either stream. For an earlier input, we used a timestamp only after a later entry in the same log confirmed that the first time had closed. That confirmation had to be recorded by the forecast time.

We found the middle value of the positive time gaps between samples in each log. Each camera bin and each target interval had to contain at least two eligible readings. The gap between readings, and from a reading to either interval edge, could be at most 9.994 milliseconds. That is twice the middle interval in the camera log. For a command sample, we looked back from the requested time and used the most recent eligible entry. It could be at most 19.990 milliseconds old, twice the middle interval in the display log.

We used the first two-thirds of the software time shared by the camera and display for fitting. The whole interval used to measure a fitting answer had to finish by the split at 2,400.006403 seconds. Every earlier reading for a later forecast, including the control reading eleven seconds back, came from the later period. No camera or display row was reused across the two periods. The timing rules left 6,732 of the 11,249 possible forecast times. Fitting had 4,440 complete examples out of 4,454. Of 2,278 later examples, 2,270 gave enough earlier information to issue all four forecasts. A separate reader checked all the saved forecasts before we read the later camera values. Two later measurements were unusable. This left 2,268 forecasts for each rule to score.

What the four rules learn

The first rule carries forward the spread of the most recent 100 milliseconds. The other three learn how much to add to that starting number. They use four earlier camera bins that each cover 50 milliseconds. For each bin, they use the average bend and how widely the bend varies.

The first fitted rule uses just those camera readings. The next fitted rule also takes ten command readings at 5, 4, 3, 2, 1, 0.50, 0.20, 0.10, 0.05 and 0 seconds before issue. The last rule takes commands at the same spacing, with each time moved another six seconds back. This makes a comparison with older command history. The older history can still carry information.

When fitting each rule, we subtract the fitting average for each kind of input and divide by its population standard deviation in the fitting cases. A kind of input that stayed constant was given no influence. We asked the fit to make its average squared misses small and also charged it 0.1 times the sum of the squared input weights. This discourages large adjustments for small changes in the measurements. The fixed offset carries no charge. A predicted spread below zero is set to zero.

Interpreting the scores

On each later case, we subtract the measured spread from each forecast and take the size of the difference. To see what the visual command added, we subtract the camera-only error from the error with the command, then average those differences. The command lowered the camera model's error in six of the 20 populated blocks on the one-minute grid and raised it in the other 14. Across all scored cases it raised the average error. Reusing the recent camera spread still gave the closest forecasts overall. These outcomes describe one recording. Testing the rule on other fish and checking the physical timing of both instruments remain separate steps.
