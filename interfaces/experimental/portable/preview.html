From a count window to two components


A large count can swamp a small one. The decoder first takes the square root of the counts and standardizes them using saved training values. The short-budget model reads the 344 recorded features directly. The full-budget model transforms each available region through its learned matrix and bias, then adds the branches into 171 computational coordinates. Those coordinates belong to an adapter’s input basis; they are not 171 measured cells.


The next stage has to carry information across twenty bins. A gated recurrent unit (GRU) does this with a running state: reset and update gates control what it retains. Its final state and the window-mean input feed the velocity head, and saved scalers return the estimate in metres per second. Changing a count changes the input to that saved computation. It does not train the model or teach a nervous system.


Both exports were selected on validation data, with that choice unchanged after the protected test. The saved study did not confirm source-transfer benefit for either budget. A model can execute the saved calculation correctly and still fail a broader scientific claim.


What the existing software comparison checked
The historical independent release comparison covered 8,330 windows per budget, two components each: 33,320 scalar outputs in total. Saved PyTorch replay was bit-exact to its reference. NumPy maximum differences were 1.4901161193847656e-08 m/s for the short-budget model and 3.725290298461914e-08 m/s for the full-budget model, against absolute tolerance 2e-6 m/s and relative tolerance 1e-5. Missing-region checks covered 100 sampled full-budget windows per condition. This was an implementation comparison, with PyTorch imports blocked for portable inference. It supplies no new movement accuracy, biological learning or current interface timing result.
