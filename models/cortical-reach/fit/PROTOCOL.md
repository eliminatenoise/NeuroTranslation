# Five-bin area 2 movement forecasts

Each forecast uses five completed 40-ms bins from one C_20170912_COactpas trial. The output is the change in the recorded handle's planar position over the next 100 ms in centimetres. The dataset records one macaque on one day. Every model operates on the same eligible windows. Spike counts come from 30 session-local positive-sort columns. Endpoint position and backward 40-ms change supply four movement features. Seven observed-cue values describe the perturbation, target and go. A cue at a bin endpoint becomes available only at a later endpoint. Chronological trial IDs, epoch, offset, rewards, future event times and counterpart trial identity stay outside the predictor.

Fit six masked versions of the same Transformer, from scratch, at seeds 17, 41 and 73. In raw order the 41 features are movement, neural, cue. Fit equal-trial-then-equal-epoch weighted population means and standard deviations across all five tokens on the fit split. Replace standard deviations below 1e-6 with one. Standardize, clip to ±8, then mask excluded columns to zero. Center dx and dy with their training means and use one shared training RMS scale for both axes (floor 1e-6). Hence squared loss weights the two physical axes equally. Masking does not change tensor shapes or parameter counts. All six models within each seed share exact initial parameter values, examples, permutations and tensor dimensions.

Embed each token with a 41-to-16 linear layer, add five learned positional embeddings, and apply a pre-normalized two-head self-attention block (head size 8). All five input tokens precede the forecast. A second pre-normalized residual block uses a 16-to-32-to-16 ReLU feedforward network. Read the final token following layer normalization and map it linearly to dx and dy. Every normalization epsilon is 1e-5. No dropout, schedules or validation-based selection. Float32 training, 24 complete shuffled passes, batch size 128, including the short final batch. In every pass each row appears once; per-window objective weight is 1 / (number of represented original trials × number of represented epochs within its trial × number of windows within its trial and epoch). For stochastic gradients, multiply weights by N and divide the weighted sum by 128, including the short final batch. Take mean squared loss over the two coordinates. AdamW lr 0.002, betas (0.9,0.999), eps 1e-8, weight decay 0.001, gradient norm clip 1.0. The native NumPy default_rng(seed) row permutations are shared by every branch. Final-epoch weights only. Report all seeds plus arithmetic mean of predictions; validation does not select architecture/branch/seed/checkpoint. There are no held-fold estimates for fit rows: any fit-block predictions are explicitly in-sample.

Wrong-trial controls replace only the five neural vectors with those of the source row's earlier same-block donor. Motion, cues and current row remain original. Exclude donor -1 from that comparison. Pairwise score details and bootstrap are separately fixed by the score owner. Validation and test predictions identify original rows and contain native dx/dy centimetres. Use the source team's released block, and score the sealed chronological test once following independent validation/weight freeze and the collector's authorization. Never mix training, validation and test during preprocessing.

Resource comparison uses a matched 24-update prefix of seed 17 and the joint model, homogeneous float32, CPU 1, CPU 2, ROCm 1. Initialize on CPU before device transfer. CPU1 is the baseline. Candidate must achieve prefix max output deviation ≤0.0005 cm versus CPU1 and be ≥10% faster on total cold invocation to change device/thread choice. No claim of full-model speed or accuracy parity from a prefix. Training uses no workers, inter-op 1, resident data and batches, capped nested pools. Torch owns CPU vectorization and ROCm kernel workgroups/dispatch, with explicit device synchronization. Portable inference uses ordinary JS arithmetic or NumPy float64, with parity tolerance 0.0001 cm against the native float32 model. Input checks cover exact unit identities, rational cue masks, finite weights and physical-size array shapes. Serial source hashing, JSON and NPZ I/O do not need GPU dispatch.
