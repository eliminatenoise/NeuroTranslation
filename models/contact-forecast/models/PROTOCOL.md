# Forecasting the next 100 ms of recorded cortical events

The response at each contact is the integer sum over ten future 10-ms samples. Inputs are five completed 40-ms tokens. Each token carries four handle measures in cm (end x, end y, last minus first x and y), the 26 prior sort-zero count totals in locked contact order, seven observed cue values (bump known and its unit direction, target known and its unit direction, go known), and three elapsed times in seconds since each visible cue. No trial ID, future direction, sample index, phase, target or donor ID is an input. The source worker controls event visibility. Offline processing can give encoder samples upstream filter support from later physical times.

Fit each branch on all represented original trials in the locked Sep 12 training archive. Weight each original equally, each of its windows equally, each of its five tokens equally in the input scaler, and each contact equally in the loss. The scaler uses training weighted population means and standard deviations, pooled by feature over tokens. A standard deviation below 1e-6 disables that input in every split, even when a once-constant cue varies later. Set its scale to 1. Clip all standardized features to ±8, then zero disabled and branch-excluded columns. The 40 inputs are partitioned into movement (4), count (26) and cue (10). The six arms use all, count_cue, cue, movement, count, movement_cue. Wrong movement uses the all weights and replaces only the first four raw columns in all five tokens using the source archive's within-phase earlier donor. Donor -1 is missing. Use all five observed tokens at every readout; no padded, partial or future tokens.

Each Transformer projects 40 inputs to width 16, adds learned position vectors (normal initialization, sigma .025), applies one pre-layer-normalized, two-head self-attention layer with residual connection (eight channels per head), then a pre-layer-normalized 16→32→16 ReLU block with residual connection. Apply layer normalization and a linear 26-output readout to the last token. All layer normalization epsilons are 1e-5. Independent positive means are softplus(logit)+1e-6 count/contact/100 ms. Initialize the output bias to inverse-softplus of the training weighted mean minus 1e-6, floored at 1e-6 inside inverse-softplus, otherwise use torch.nn.Linear defaults. No dropout. Loss for response y and predicted mean m is m−y log(m), omitting the constant log(y!). Three CPU-initialized seeds 17, 41, 73, one initial state per seed shared across arms. Keep all final fitted weights. No early stopping, seed, checkpoint or architecture selection. Float32 AdamW with learning rate .002, betas .9/.999, epsilon 1e-8, decay .001 on all parameters, gradient norm clip 1.0, foreach/fused off. Repeat 24 training passes, batch size 128, every row once per pass including the short batch. Use NumPy default_rng(seed).permutation for each pass, shared across arms. Multiply row weights by N and divide the minibatch sum by 128. Progress and comparisons use the native predictions for each seed separately.

Fit one deterministic log-link Poisson regression per arm, all 26 contacts independently by joint vectorized optimization, with the same features, masks and weighting. Flatten the five standardized tokens in chronological order to 200 inputs. Use all 200 coefficient slots even for omitted features; start coefficients at zero and intercepts at log(max(training mean,1e-6)). In float64 minimize the sum across contacts of the weighted windows' (exp(z)−y*z), plus 0.03/2 times the total squared coefficient norm. The sum is proportional to equal-contact averaging with the same per-contact penalty. Leave all intercepts unpenalized. Full-batch Torch L-BFGS strong Wolfe line search, history 20, lr 1, 300 iterations, 450 closure evaluations, gradient tolerance 1e-8, change tolerance 1e-12. Record final objective, iterations and largest absolute gradient. Mark final gradient above 1e-5 or a nonfinite result as a failed fit. One deterministic fit per arm has no seed axis. All Transformer arms have the same nominal parameter count within that family; all regressions do too. The two families have different capacities.

Compare CPU one thread, CPU two threads and one available ROCm device on the same seed-17/all first 24 updates on the training data. Default CPU1. Switching the Transformer training route requires max prediction difference across 32 training probes ≤0.0005 count and at least 10% lower cold process time. Take the qualifying fastest. CPU1 handles float64 regressions and portable inference. One interop thread, no loader workers, fixed row order, capped nested pools, one fitting process at a time. Use highest float32 matmul precision. Torch owns kernel selection, workgroup sizes and scheduling; record the actual hardware and timing. No full-training acceleration or universal parity claim follows from a prefix. Before opening validation, freeze weights, input scaling, indices, source hashes and optimizer settings. No test numerical input or output before the study's hash-bound release. On each released split compute native forecasts once, cross-check separately implemented NumPy inference for every available forecast (absolute tolerance 1e-4 for Transformer and relative 1e-10, absolute 1e-10 for regressions), then save predictions with seeds, trial, k, phase, offset, direction and donor. The scores and chronological resampling are described in the companion statistical study.
